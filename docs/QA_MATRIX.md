# Yuval - enterprise QA matrix

Manual test matrix for IT / QA before a broad rollout. Companion to [DEPLOYMENT.md](DEPLOYMENT.md) (how to
install) and [ARCHITECTURE.md](ARCHITECTURE.md) (what the codes and states mean).

## How to read this

**STATUS** is exactly one of:

- `Automated (test name)`: the behaviour that the scenario's expected result depends on is exercised by the
  named unit test(s) (cargo test = snake_case names, vitest = quoted names with the file). Automation does
  not replace a run on a real machine; the "Not covered by automation" column says what a human still has to
  look at.
- `Verified live on dev box (details)`: observed on the development PC in a real run (Windows 11 Enterprise,
  build 26200 / 25H2, Classic Outlook installed but not running, New Outlook installed, 100% DPI single
  monitor), with evidence from `%LOCALAPPDATA%\Yuval\logs\yuval.log`. The dev box is not a
  Windows 10 21H2 machine: nothing Windows-10-specific is claimed as verified.
- `Needs hardware/VM (why)`: cannot be proven by the repository's tests or on the dev box. Run it on the
  listed environment.

Rules for this track: Outlook was never launched on the dev box and no real calendar text was read, so every
scenario that needs a live Outlook is `Needs hardware/VM`. One later exception (2026-10-06): the read-only
`outlook_live` cargo test was run against the developer's own, already running Classic Outlook to check the
category-color and meeting-request reads; it prints counts only (rows E26, E27). Codes and states are defined in
ARCHITECTURE.md (sections 4 and 8).

### Test environment (the matrix assumes this unless a row says otherwise)

| Item | Value |
|---|---|
| OS | Windows 10 21H2 (build 19044) x64, fully patched; repeat key rows on 22H2 and Windows 11 |
| User | **Standard user, no local admin** (UAC on) for every run; admin only for installing and for changing policies |
| Install | `Yuval_1.0.0_x64-setup.exe /S` as admin; user signs out and in; island visible at top centre |
| Outlook | **Classic Outlook** (Microsoft 365 Apps), Exchange account, Cached Exchange Mode on unless stated; calendar with test meetings only (no real data in screenshots or tickets) |
| Evidence | Log file `%LOCALAPPDATA%\Yuval\logs\yuval.log` and Settings tab > "Copy diagnostics" |
| Log line shape | `<time> <LEVEL> [calendar] status <from> -> <to> code=<CODE or -> events=<n>` for connection changes; `[ui:reminders] fire <8 hex> (<n> min before)` for a fired reminder |

Timing facts used in expected results (from `src-tauri/src/calendar.rs`): process check every 15 s while
idle or connected; re-read every 60 s while connected; attach retries after 1, 2, 4, 8, 16, 30, 30, 30 s
(about 2 minutes) before `failed` / `OUTLOOK-102`; failure backoff 5, 10, 20, 40, 60, 120, 300 s (+-20%);
watchdog 10 s; five abandoned reads settle on `failed` / `OUTLOOK-109` with at least 5 minutes between
tries. Reminder alert stays 8 s (hover pauses it); default reminder is 30 minutes before start.

## 4. Coverage honesty notes

- Where a row says `Automated`, the test pins the decision logic (state machine, classification, scheduling,
  parsing, layout maths). No automated test drives a real Outlook, a real display change, a real sleep, the
  installer, or the Windows logon/logoff path. Those parts are the "Not covered by automation" column.
- The Yuval Center (rows E33 to E46) has three kinds of tests: `cargo test --lib` for the Rust half (notes,
  the page rule, the pipe server over a real named pipe), `npx vitest run` for the island's Notes tab, the
  settings control and the tour page, and `dotnet test center/CompanyIsland.Center.Tests` (xunit) for the Center's
  Core library (pipe client, models, note helpers, strings) against an in-process fake pipe server. The Center's
  XAML pages, its window, the single-instance redirect, the WebView2 host of the tour and the installer have no
  automated tests; the rows above say so. The Center was first run against the real island's pipe on
  2026-10-07 (dev box, Windows 11 build 26200, DPI 96; island driven via CDP synthetic input and the Center via UI
  Automation, no real mouse, no foreground window and no desktop capture in that session); it has not been run on
  Windows 10 or at a DPI above 100%. Not covered by that run: bringing the Center to the foreground, arrival toasts,
  the unseen indicator states, pipe access from another user or session, the installer (needs UAC), an oversized
  notes file and network traffic of the Center.
- Graceful `taskkill /IM Yuval.exe` (no `/F`) does not close the island (observed on 1.0.3 and 1.0.4), so the
  installer's graceful stop step is always followed by Tauri's forced kill.
- Counts of passing tests change with every commit; run `npm test` and `cargo test --lib` (in PowerShell with
  `%USERPROFILE%\.cargo\bin` on PATH) before a QA cycle and attach the output; add `dotnet test center/CompanyIsland.Center.Tests`
  (.NET 10 SDK) for the Center.
- The dev box evidence above is from 2026-10-06 and 2026-10-07 and from build 26200 only.
