# CompanyIsland - enterprise QA matrix

Manual test matrix for IT / QA before a broad rollout. Companion to [DEPLOYMENT.md](DEPLOYMENT.md) (how to
install) and [ARCHITECTURE.md](ARCHITECTURE.md) (what the codes and states mean).

## How to read this

**STATUS** is exactly one of:

- `Automated (test name)`: the behaviour that the scenario's expected result depends on is exercised by the
  named unit test(s) (cargo test = snake_case names, vitest = quoted names with the file). Automation does
  not replace a run on a real machine; the "Not covered by automation" column says what a human still has to
  look at.
- `Verified live on dev box (details)`: observed on the development PC in a real run (Windows 11 Enterprise,
  build 26200 / 25H2, Classic Outlook installed but not running, New Outlook installed, 100% DPI single
  monitor), with evidence from `%LOCALAPPDATA%\CompanyIsland\logs\companyisland.log`. The dev box is not a
  Windows 10 21H2 machine: nothing Windows-10-specific is claimed as verified.
- `Needs hardware/VM (why)`: cannot be proven by the repository's tests or on the dev box. Run it on the
  listed environment.

Rules for this track: Outlook was never launched on the dev box and no real calendar text was read, so every
scenario that needs a live Outlook is `Needs hardware/VM`. Codes and states are defined in
ARCHITECTURE.md (sections 4 and 8).

### Test environment (the matrix assumes this unless a row says otherwise)

| Item | Value |
|---|---|
| OS | Windows 10 21H2 (build 19044) x64, fully patched; repeat key rows on 22H2 and Windows 11 |
| User | **Standard user, no local admin** (UAC on) for every run; admin only for installing and for changing policies |
| Install | `CompanyIsland_1.0.0_x64-setup.exe /S` as admin; user signs out and in; island visible at top centre |
| Outlook | **Classic Outlook** (Microsoft 365 Apps), Exchange account, Cached Exchange Mode on unless stated; calendar with test meetings only (no real data in screenshots or tickets) |
| Evidence | Log file `%LOCALAPPDATA%\CompanyIsland\logs\companyisland.log` and About tab > "Copy diagnostics" |
| Log line shape | `<time> <LEVEL> [calendar] status <from> -> <to> code=<CODE or -> events=<n>` for connection changes; `[ui:reminders] fire <8 hex> (<n> min before)` for a fired reminder |

Timing facts used in expected results (from `src-tauri/src/calendar.rs`): process check every 15 s while
idle or connected; re-read every 60 s while connected; attach retries after 1, 2, 4, 8, 16, 30, 30, 30 s
(about 2 minutes) before `failed` / `OUTLOOK-102`; failure backoff 5, 10, 20, 40, 60, 120, 300 s (+-20%);
watchdog 10 s; five abandoned reads settle on `failed` / `OUTLOOK-109` with at least 5 minutes between
tries. Reminder alert stays 8 s (hover pauses it); default reminder is 30 minutes before start.
